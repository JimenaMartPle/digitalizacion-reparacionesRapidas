# Digitalización · Reparaciones Rápidas

Resumen del trabajo realizado en las unidades didácticas del módulo **Digitalización aplicada al sistema productivo**. El caso de estudio es Reparaciones Rápidas, una empresa ficticia de reparación de dispositivos.

## UD1 · ¿Qué significa digitalizar una empresa?

[Ver la unidad completa](https://marcsemperlloret.com/es/docencia/digitalizacion/ud1-que-significa-digitalizar-una-empresa/)

La unidad analiza cómo pasar de una empresa tradicional a una digital. El punto de partida es el problema real: primero se identifica la necesidad y después se propone una solución tecnológica, justificando qué cambia y qué límites tiene.

1. [**Sesión 1 · Qué cambia realmente al digitalizar**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud1-que-significa-digitalizar-una-empresa/sesion-1/): se evalúan ocho propuestas para el taller, distinguiendo cambios de soporte, cambios de proceso y propuestas que no concretan una acción. Cada dictamen se justifica con hechos del caso y explica qué ocurriría después de aplicar la propuesta.
2. [**Sesión 2 · Rediseña una empresa**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud1-que-significa-digitalizar-una-empresa/sesion-2/): se identifican problemas y necesidades, se diseña el proceso futuro y su arquitectura, y se justifican las tecnologías elegidas. También se compara el proceso actual con el rediseñado y se descarta una alternativa explicando el motivo.
3. [**Sesión 3 · Revisión y defensa de la propuesta**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud1-que-significa-digitalizar-una-empresa/sesion-3/): se corrige la propuesta a partir de observaciones, se aclaran responsables, viabilidad y datos pendientes, y se defiende una implantación gradual mediante un piloto.

**Producto de la unidad:** un único registro acumulativo con el análisis, el rediseño y la versión revisada de la propuesta para Reparaciones Rápidas.

## UD2 · Integración y automatización de sistemas

[Ver la unidad completa](https://marcsemperlloret.com/es/docencia/digitalizacion/ud2-integracion-y-automatizacion-de-sistemas/)

La unidad estudia cómo se comunican las aplicaciones y cómo automatizar tareas mediante APIs, eventos, polling, webhooks y colas. Se elige el mecanismo según el problema y se prevén respuestas incompletas, interrupciones y otros fallos.

1. [**Sesión 1 · Cómo se comunican las aplicaciones**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud2-integracion-y-automatizacion-de-sistemas/sesion-1/): se distingue una petición a una API de un evento, se comparan polling y webhook y se explica el papel de las colas y las herramientas low-code/no-code. El sitio desarrolla esta sesión con una simulación del cierre de una reparación y su petición de factura, incluyendo indisponibilidad, reintentos, duplicados y datos obligatorios ausentes.
2. [**Sesión 2 · Diseña la automatización de una empresa**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud2-integracion-y-automatizacion-de-sistemas/sesion-2/): se diseña y justifica un flujo de automatización para el caso empresarial.
3. [**Sesión 3 · Pruebas de integración, gestión de fallos y consolidación**](https://marcsemperlloret.com/es/docencia/digitalizacion/ud2-integracion-y-automatizacion-de-sistemas/sesion-3/): se comprueba el flujo, se tratan los fallos y se consolida la propuesta.

**Producto de la unidad:** una automatización diseñada y simulada, con sus decisiones y comprobaciones documentadas.
